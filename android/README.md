# 自用路由线路 · Android

连接路由器，查看和切换已保存的 AnyTLS 线路，并管理路由器的分流与附加功能。原生 Android App，不接管手机流量，也不创建 VPN。

[下载 Android 1.4.0 APK](https://github.com/hjh006/router-playground/releases/download/android-v1.4.0/router-control-1.4.0.apk) · [路由端测速更新包](https://github.com/hjh006/router-playground/releases/download/android-v1.4.0/latency.tar.gz) · [两端源码与校验文件](https://github.com/hjh006/router-playground/releases/tag/android-v1.4.0)

当前版本为 **1.4.0**，包含下述插件控制，线路卡片显示由路由器测得的节点入口 TCP 延迟。APK 沿用原签名，可直接覆盖升级；完整维护源码包含 App、路由端 overlay、补丁和运行工具，不包含本地私有工作目录。

## 支持范围

- Android 8.0 及以上。
- 当前兼容目标：Netgear R7000，Merlin 380.70_0-X7.9.1。线路读取/切换沿用 r3 接口，新控制按增强插件 r5 的能力字段启用；不支持的分组不提供保存。其他固件及插件接口尚未验证。
- 手机需要能访问路由器管理地址，通常连接家庭 Wi-Fi。HTTP 仅接受局域网 IPv4；HTTPS 使用系统证书校验。

## 使用

1. 安装 APK，填写路由器管理地址并登录。地址、账号和线路由自己配置，安装包不携带这些内容。
2. App 读取路由器已保存的 AnyTLS 线路，按名称归类国家或地区，显示国旗、数量及可折叠分组。正常宽度采用两列，小屏或大字体自动改为单列；分类不能代替实际出口位置检测。
3. 点击分组的“测延迟”，路由器逐条测量该组节点入口的 TCP 建连耗时，显示毫秒数、进度和停止按钮。手机只读取结果；App 不自动后台批测。该功能需要下述入口 TCP 仅测速组件，旧插件或旧 HTTPS 测速组件不满足新协议时会明确提示。
4. 点击线路的“切换”并确认，等待配置与新的健康检测；结果未知时先刷新核对，再决定是否重试。

5. 首页“直连 / 代理 · 插件控制”进入设置。先读取当前值，只提交你实际修改的分组；保存前说明代理是否需要短暂重载。广告开关与代理开关会继续等待相应运行状态；固件异步应用尚未完成时，页面提示等待和刷新，不重复提交。返回首页会重新读取线路及状态。

| App 原生控制 | 提供的功能 |
| --- | --- |
| 直连与代理 | 手动关闭/开启路由器代理，gfwlist、大陆白名单、全局代理等原插件模式 |
| 设备与 UU | VPN 整机旁路、UU 共存 MAC 名单、其他 TCP 的规则分流/境外代理/直连、检查间隔 |
| 访问控制 | 默认主机策略与已有 IP 规则的策略/端口；新增和删除通过完整面板完成 |
| 自动故障切换 | 同地区优先、候选 ID、地区映射、失败/恢复次数、冷却、超时、预算、故障直连保护及运行状态 |
| 广告过滤 | 开关、额外拦截/放行域名、专用热保存及运行/排空状态 |
| 连接与检测 | AnyTLS 空闲连接、握手、ALPN、TLS 指纹、Hosts，HTTPS 检测间隔/超时/失败阈值 |
| 节点解析 | 节点独立 DNS 解析预设与自定义上游 |

设置里的“原插件完整面板”在 App 内打开路由器原页面，提供其余 DNS、规则、日志及维护功能；该入口使用插件原界面。线路新增/编辑/删除也仍由原面板完成，原生线路页保持只选择现有线路。

原面板的配置导入使用系统文件选择器，仅授权本次选择的文件；导出使用系统保存窗口，仅读取插件固定的备份入口。备份可能含线路密码与设备信息，请自行保管，不提交到源码仓库。导入/恢复仍使用插件原行为，可能覆盖现有设置并重载服务。

全局“直连”会手动关闭本插件代理；自动切换不会重新启用它。“故障直连保护”是线路失败时的自动保护策略，两者不同。UU 设备的“直连”只跳过本插件，不关闭 UU。AnyTLS 模式的代理能力仍以插件实际支持的 IPv4 TCP 为准。

除广告过滤使用 `ss_adblock.sh` 热保存外，设置复用插件的 `ss_config.sh` 应用流程，可能短暂重载代理与插件 DNS。App 不调用内部故障切换命令、不操作 UU 原进程。未编辑的配置、旁路名单、节点内容及自动更新开关不回写；订阅和规则自动更新保持原状。配置读回成功只证明保存已确认，不能代替代理或游戏连通性验收。

保存前会重新读取配置；如果本分组或当前线路已在浏览器/后台改变，App 拒绝旧页面提交并要求刷新。未知结果不自动重试，先刷新核对。原插件完整面板沿用原插件的保存行为，编辑时避免同时在多个客户端操作。

线路卡片的“入口 TCP”表示路由器到已保存节点入口的 TCP 建连耗时。每条任务进行 3 次建连，单次最多 5 秒；只有 3 次全部成功且路径已验证时，才显示成功耗时的中位数，数值范围为 0–5000 ms。每条任务共有 25 秒预算，包含入口解析、路径核对和采样；路由器一次只测一条，手机按分组排队读取结果。

入口地址按现有节点解析和 Hosts 获取。探测程序只对入口发起 TCP 建连，不进行节点认证；毫秒数不证明 AnyTLS 线路、出口网站或下载速度可用，完整代理连通性另看首页的 HTTPS 健康检测。只有能确认连接未被透明代理截获的路径才显示数值；无法确认时，组件返回 `path_unverified`，卡片显示“路径待确认”，不显示可能失真的低延迟。

独立测速不切换当前线路，不改节点解析、Hosts、代理开关、UU、旁路、DNS 或防火墙。任务仅运行自己的 TCP 探测进程，结束后清理自身临时状态。结果保存在 RAM，包含线路编号、任务编号、状态、毫秒数及采样时间，不包含节点入口或密码。App 只接收与本次任务和线路相符的结果；入口、Hosts 或节点解析设置变化会使旧缓存失效，超过五分钟提示重测，过期结果不再显示为绿色。

“停止”会请求取消当前任务并停止后续排队；只有读到路由器终态才显示已确认结束。手机断网时保留已完成结果，恢复连接后继续读取，未确认结果不会被标成线路超时。

首页当前线路的 HTTPS 健康状态仍复用固件原有检测入口，与手动逐条入口 TCP 延迟分别显示。App 前台每 30 秒读取状态，进入后台后停止定时刷新。

## 仅测速组件

现有增强 r5 需要增加测速脚本、固定启动入口、TCP 探测程序和能力描述，才能提供逐节点入口检测。独立离线包只安装这四个运行文件并初始化 RAM 状态，不重装插件、不重启服务、不提交线路或网络配置。下载本页的 `latency.tar.gz`，保持文件名不变，通过软件中心的“离线安装”上传。它不是完整插件安装包，不能在空白路由器上首次安装。

旧固件只用裸脚本名分发任务。App 先向经过登录验证的上传入口提交只含任务和线路编号的 RAM 请求，确认上传后调用固定脚本名；不把参数拼到命令行，也不向 DBus 写测速参数。请求被完整校验并原子领取，结果仍须匹配本次任务和线路编号。

1.4.0 要求能力描述和结果均为 `method=router_tcp`、`target=entry`、`transport=ram_mailbox_v1`；旧 HTTPS 结果不会显示成入口 TCP 延迟。`path_unverified` 是独立终态，不能携带成功毫秒数。采样详情等额外字段可由组件提供，不影响 App 的这组校验。

从仓库根目录使用已经由 `scripts/prepare.py` 准备的集成树构建：

```sh
python3 scripts/build_latency_addon.py --prepared-plugin build/local/r7000-enhanced
```

默认输出 `outputs/r7000-latency/latency.tar.gz` 及 SHA-256 校验文件。包中只有本项目的 TCP 探测程序、测速脚本、安装脚本、能力描述和许可，不携带上游二进制或用户配置；构建时需要已准备的 `r7000-client/dist/ss-tcp-probe-linux-armv5`。

登录会话加密保存在手机本地，备份已禁用；线路配置只保留在内存。路由器在其他设备重新登录后可能使旧会话失效，届时重新登录即可。请勿把管理凭证、私有配置或包含这些信息的截图提交到仓库。

## 本地构建

支持 macOS、Linux，需要 Python 3、JDK 17 或更新版本，以及本地 Android SDK。默认使用 SDK Platform `android-36.1` 和 Build Tools `36.1.0`，不使用 Gradle，不自动下载依赖。

```sh
python3 android/build.py
```

SDK 依次从 `--sdk`、`ANDROID_SDK_ROOT`、`ANDROID_HOME` 读取；未指定时，macOS 查找 `~/Library/Android/sdk`，Linux 查找 `~/Android/Sdk`。JDK 优先使用 `JAVA_HOME`，否则在 macOS 使用 `java_home`，在 Linux 从 `PATH` 查找 `javac`。

```sh
python3 android/build.py --sdk "$ANDROID_SDK_ROOT" \
  --platform android-36.1 --build-tools 36.1.0 \
  --signing-dir "$HOME/.local/share/router-control/signing" \
  --output /tmp/router-control-local.apk
```

默认输出 `android/build/router-control-<版本>.apk` 及 `.apk.sha256`。`android/build/` 是本地忽略的缓存和产物目录。

签名身份由 `--signing-dir` 或 `ROUTER_ANDROID_SIGNING_DIR` 指定，必须位于仓库之外。默认目录为 macOS 的 `~/Library/Application Support/RouterControl/signing`，或 Linux 的 `$XDG_DATA_HOME/router-control/signing`（未设置时使用 `~/.local/share/router-control/signing`）。目录权限为 `0700`，密钥和随机密码文件权限为 `0600`，密码不写入命令行或日志。

请保存同一目录中的 `router-control.p12` 和 `signing-password`：相同签名身份决定后续 APK 能否覆盖升级。自己构建默认会生成新的身份，与公开 Release 的签名不同，不能直接覆盖安装 Release；卸载重装会清除本地登录状态。不要提交或分享签名目录。
